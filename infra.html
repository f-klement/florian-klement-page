Infrastructure

Private infrastructure

A self-hosted Kubernetes platform, reproducible from code

Four nodes running K3s, backed by a TrueNAS SCALE storage host and fronted by a UniFi edge. The whole platform is rebuilt from a bootstrap script and one Helm chart; the only manual step is the one-time initialisation of the secrets store. The numbers below are a snapshot from September 2026.

4 nodes 18 cores, 62 GiB memory
92 pods 144 containers, 25 namespaces
32 Argo CD applications all auto-synced from main
60 Deployments plus 39 CronJobs, 8 DaemonSets
36 NetworkPolicies default deny where it matters
96 container images every one pinned by digest

Architecture

The recursive edge is the thing to hold on to: the storage host also runs one of the compute nodes, as a privileged LXC sharing the host kernel. That single fact explains the storage placement rules, the loopback NFS deadlock described below, and why a NAS reboot is a cluster event.

How it is built

Delivery

A merge to main is the deploy. Renovate proposes, CI gates, Argo CD applies, and no single credential can both author a change and ship it.

How it works

GitLab CI runs tests, dependency audits and a Trivy scan for secrets, dependencies and the image before anything reaches the registry. Renovate opens version bump merge requests and automerges routine ones; roughly a dozen high blast radius packages and every major version wait for a human click.

All 32 Argo CD applications auto-sync, so there is exactly one gate per change. Images are pinned by digest, each written in exactly one place. A gate that always passes is not a gate: where a second manual step was removed, it was replaced by a CI check that fails the merge, not by trust.

Three things sit deliberately outside GitOps: node upgrades (they cordon nodes and swap binaries, not containers), the vendored Wazuh manifests, and secret values, which no reconciler can supply. Argo CD replaced a hand written redeploy poller that classified commits by changed path and misidentified more than half of the chart bumps.

Security

Five tools, five boundaries, one pane. Each covers something the others cannot see, and all of them forward into Wazuh.

How it works

The edge router handles packets and intrusion prevention. CrowdSec reads the ingress logs and runs an application layer WAF, banning at the edge with escalating durations; a firewall bouncer on every node drops banned sources on all ports, and its chains fail open, so a crash costs protection, never access. Falco watches syscalls through eBPF, ClamAV scans on a schedule, Lynis audits host posture weekly.

Wazuh (HIDS and SIEM) correlates all of it, with curated realtime file integrity monitoring on every node. The two hosts that cannot run an agent, the NAS and the router, report over syslog through a relay so both Loki and Wazuh receive a copy. High severity alerts page via Telegram.

Argo CD is the most privileged workload and is fenced accordingly: a default deny NetworkPolicy pair limits it to DNS, the API server and outbound HTTPS. The chart's own policies had to be disabled to get there, because its shipped server policy allowed ingress from every pod in the cluster, and NetworkPolicies are additive. Found by reading the live object, not the chart.

Observability

Grafana Alloy collects logs, metrics and traces into Loki, Mimir and Tempo on MinIO. Alerting is split between the SIEM and Gatus, and the pager has a check that watches the pager.

How it works

All three signals persist to MinIO on NVMe. A nightly job mirrors the day's objects to a compressed dataset on the HDD pool, so the spinning disks stay asleep instead of absorbing continuous writes.

Gatus does not probe ports. Its interesting checks query Mimir: unavailable replicas anywhere in the app namespace, exporters that have stopped producing metrics, and Argo CD applications that can no longer be rendered. That last case is invisible from every other angle, because the pods keep running while the cluster silently stops tracking git.

Readiness probe coverage went from 7 to 19 of 31 containers, which is what gave the replica metric meaning: a container without a probe is Ready the moment it starts. Exporter sidecars deliberately have none, because a pod is only Ready when every container is, and a probe on a sidecar would pull the application out of its Service. Monitoring failure would cause an outage.

Identity

One account per person in LLDAP, one group as the single access gate. Removing someone there revokes everything at once.

How it works

Authelia provides the login portal and acts as OIDC provider, binding read-only to LDAP. Browser-only apps sit behind forwardAuth. Apps with native clients that cannot follow a login redirect bind to LDAP directly. Argo CD uses both: forwardAuth keeps anonymous traffic off it entirely, and OIDC tells its own RBAC who you are.

LDAP rather than an OIDC-first design because it is the common denominator across the services that matter here. Apps behind forwardAuth are ClusterIP only: a NodePort would SNAT traffic into the pod CIDR that the identity header trusts, making it forgeable from any host on the LAN.

Storage

ZFS on the NAS, three pools tuned by record size, three paths into pods. Databases stay off NFS by design.

How it works

An NVMe pool with small record sizes holds service configs and databases, bind-mounted as hostPath into the LXC node. A second NVMe pool backs democratic-csi for dynamically provisioned volumes (observability, Wazuh, Endpaper). The HDD pool serves bulk data over static NFS volumes and holds the cold archive and snapshot replication.

SQLite and MariaDB locking over NFS is unsafe, so anything database-bearing uses hostPath. iSCSI is impossible here: the LXC worker's network namespace blocks the kernel initiator, which is also why Longhorn was abandoned. Backups are ZFS snapshots replicated to a second pool, on-box only.

Lessons from incidents

  1. 01

    The loopback NFS deadlock

    The LXC's NFS client and the host's NFS server share one kernel, one page cache and one reclaim path. Under a burst of concurrent writers an nfsd thread entered direct reclaim, landed on dirty pages of an NFS client mount, and waited on an RPC to a server whose every thread was in the same wait. Every export was down for hours and needed a power cut. The media path now bypasses the NFS client entirely via hostPath, which is a reduction, not a cure, and documented as such.

  2. 02

    Ready for 39 hours through a storage outage

    A pod stayed healthy through a total storage outage because its probe ran a real query through an already open SQLite file descriptor served from page cache, while fresh opens on the same mount hung forever. A probe that reuses a long-lived handle measures the process, not its storage. Probes now perform a namespace operation with an internal timeout shorter than the probe timeout.

  3. 03

    The deploy console reachable from any pod

    Argo CD's chart ships a NetworkPolicy for its server that allows ingress from any pod in any namespace. Policies are additive, so a narrower one cannot subtract it, and the console bypassed both the LAN-only allowlist and the login for anything inside the cluster. Found by reading the live object after install; fixed by disabling the chart's policies and writing a default deny pair.

  4. 04

    CI starving etcd

    Build pods once saturated the control plane and restarted k3s 26 times in an afternoon. CI is now pinned hard to a dedicated node, not merely preferred, because a scheduling preference would let it recur under memory pressure, the exact condition that caused it.

  5. 05

    The alert that fired once

    Gatus never re-notifies while an alert stays triggered, so an eight day outage produced exactly one message, on day one. Wazuh rules now provide the escalation Gatus structurally cannot, and every scheduled job whose only output is an exit status has something that reads that status. A suppression rule is replayed against real events rather than verified by reading, because silence cannot distinguish a working filter from a source that went quiet.

Known constraints

  • The LXC node runs privileged and unconfined, which the nested kubelet needs. A pod escape could reach host root and the bind-mounted datasets. An unprivileged migration with ID mapping is planned and clone-tested.
  • Backups are on-box only. Snapshots replicate to a second pool on the same host; there is no offsite copy yet.
  • A NAS reboot is a cluster event. It takes the LXC node down and, because the CI node hangs off the same bridge, CI with it.
